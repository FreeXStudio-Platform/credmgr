# Code of conduct

## The short version

Be decent. Assume good faith. Argue about the code, not the person.

## What is expected

- **Technical disagreement is welcome; contempt is not.** "This is wrong because X" is a
  contribution. "Only an idiot would write this" is not.
- **Assume competence.** Someone who missed something obvious probably had a reason, or was
  tired, or is new. Ask before concluding.
- **Be patient with beginners.** Everyone writing a credential manager was once someone who
  kept keys in a text file.
- **Accept a decline gracefully.** Not every good idea fits this project. `CONTRIBUTING.md §5`
  lists what is likely to be declined and why, so you can find out before you build it.
- **Report security issues privately** ([SECURITY.md](SECURITY.md)). Publishing a working
  exploit against a credential vault before it is fixed puts real people's keys at risk. That
  is a conduct matter here, not only a technical one.

## What is not acceptable

Harassment, discrimination or slurs of any kind · personal attacks · deliberately publishing
someone's private information · sexualised language or attention · sustained disruption ·
encouraging any of the above.

This applies in issues, pull requests, commit messages, code comments, and any project space.

## Enforcement

This is a small project maintained by the FreexStudio team. Reports go to the maintainers through a
GitHub Security Advisory or a private channel — they will be read and taken seriously, and
kept confidential.

Responses, in proportion: a private word · a public correction · removal of a comment ·
a temporary block · a permanent ban. Serious or repeated behaviour goes straight to the end
of that list.

There is no committee and no appeals process. The maintainers decide, explain the decision,
and apply it consistently.

## Scope

Project spaces, and public spaces when you are representing the project.
