Help
reading the graph
Filled circle — global, the one node every other node can read. Ringed circle — a project. Thinner ring — a sub-node. Dashed ring — orphaned, sealed items with nowhere to live.
Each project's inner mark is a fingerprint of its name — decorative, not a category. Small dots orbiting a node are its entries; colour is a hash of the entry's id, never its name or value.
⌐ means 2FA on reveal is set on the node (recorded; the 2.0.0-beta.1 broker does not enforce it yet), ‖ means the node itself is locked. A dashed line with an arrowhead is a grant — it points from the trusted node to the node it can see into.
Drag one node onto another to propose a grant between them. T switches to the tree view — a full keyboard- and screen-reader-accessible peer to the graph, never a fallback.
sealing
Removing a node never deletes it. "Seal" moves its entries to Orphaned, where names stay visible but values need Touch ID and a fresh 2FA code to open — every time, no exceptions for agents. Settings → Nodes lists everything sealed in the last 7 days with a one-click Restore, which brings the node, its sub-nodes, its links and its entries back exactly as they were.
grants
Isolation between nodes is the default — nothing can see into anything else until you say so. A grant names a from-node, a to-node, which capabilities (list, read, reveal values, notes), an expiry, and a reason. It shows as a dashed edge on the graph and can be revoked from Settings → Grants at any time, in either mode.
security levels · not in beta.1
Open — no prompts. Reveals return immediately. Isolation between nodes is still absolute.
Guarded (default) — high and critical reveals wait for one Touch ID tap. Everything else flows.
Sealed — every reveal, create and update waits for a tap. For the node holding the wallet.
agents · not in beta.1
An agent wired in from Settings → Agents reads and writes credentials the same way you do, scoped to the node its work folder belongs to. It can never create a grant, read another node, read sealed data, read a 2FA seed, change permissions, or purge the audit log — those are absent from its vocabulary, not merely denied.
notes
+ New note in the inspector adds an entry whose only field is free text — for anything that is not a credential. It is stored and audited like any other entry. Its text shows directly; change the field type in the preview before saving if you want it masked.
writing while locked
An entry added while the vault is locked is not written to the manifest. It waits in the pending tray — the “held” chip in the header, or Pending writes in the vault menu. After you unlock, a banner reports how many are waiting; each is accepted or discarded on its own, with its node, name and field count shown and never its values.

privacy

CredMgr has no server, so there is nothing to collect. No account, no telemetry, no crash reporting, no analytics, no cloud sync. The app makes no network requests: no HTTP client is linked into it, and the window’s content policy refuses every request that is not to the app itself. It talks to the broker over a local socket only.

Backups are encrypted files the broker writes in the vault’s own backups folder, under a passphrase you choose. Nothing about your vault — its structure, its node names, its contents — leaves this machine unless you copy a backup file somewhere yourself. A revealed value lives in memory for the reveal window and is cleared when you lock; it is never written to storage or to a log.

The app never sends anything for a donation. If you choose to e-mail a donation proof to get a supporter code, that e-mail and its attachment reach the maintainer like any other e-mail you send.

what this window keeps on disk

Only these small settings, in the window’s local storage. None of them holds a secret or a value.

  • credmgr_cosmetics — app mark, glyph weight, halo, supporter ring, node shape, colours, backdrop
  • credmgr_keys — set to off only if you turn single-key shortcuts off
  • credmgr_donate_unlocked — set after a supporter code is entered: hides the reminder
  • credmgr_extras_key — the key that opens the sealed extras on this device, kept after the code is entered once
  • credmgr_usage — days with an unlock, which reminders were shown, and whether you opted out: dates only, no entry names or counts
  • credmgr_gposV, credmgr_gpos, credmgr_gposEntry — where nodes and entries sit on the graph
  • credpong_best, credpong_level — the CredPong score
  • credgames.<game>.best, .level — the score of each further CredGames title
