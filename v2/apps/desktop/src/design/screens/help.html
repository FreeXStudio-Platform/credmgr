reading the graph
Filled circle — global, the one node every other node can read. Ringed circle — a project. Thinner ring — a sub-node. Dashed ring — orphaned, sealed items with nowhere to live.
Each project's inner mark is a fingerprint of its name — decorative, not a category. Small dots orbiting a node are its entries; colour is a hash of the entry's id, never its name or value.
⌐ means the node itself is locked, ‖ means the node asks every caller but you for a second factor on reveal (requireTwoFactor, enforced by the broker once a second factor is set up). You, logged in, are already past it; the chip on the node gives the factor on purpose and opens a five-minute window, for the whole vault, for them. A dashed line with an arrowhead is a grant — it points from the trusted node to the node it can see into.
Drag one node onto another to propose a grant between them. T switches to the tree view — a full keyboard- and screen-reader-accessible peer to the graph, never a fallback.
sealing
Removing a node never deletes it. "Seal" moves its entries to Orphaned, where names stay visible but the values cannot be opened from this app: that needs presence (Touch ID), which this beta cannot attest yet. A sealed node can be brought back within 7 days; Settings → Nodes offers Restore for nodes sealed since the app started.
grants
Isolation between nodes is the default — nothing can see into anything else until you say so. A grant names a from-node (the one that receives access), a to-node, which capabilities (read, reveal values, notes) and a reason. It shows as a dashed edge on the graph and can be revoked from Settings → Grants at any time, in either mode. Creating a grant needs presence (Touch ID), which this beta cannot attest yet, so the broker refuses it; grants made elsewhere are listed and can be revoked here.
notes
+ New note in the inspector adds an entry whose single value is free text — for anything that is not a credential. It is stored, masked until you reveal it, and audited like any other entry.
writing while locked
An entry added to a locked node is not written to the manifest. It waits in the pending tray — the “held” chip in the header, or Pending writes in the vault menu. When you open the vault, a banner reports how many are waiting; each is accepted or discarded on its own, with its node, name and field count shown and never its values.
